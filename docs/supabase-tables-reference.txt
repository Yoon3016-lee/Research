2. public 스키마 테이블 (13개)
================================================================================

--------------------------------------------------------------------------------
2.1 surveys — 설문 마스터
--------------------------------------------------------------------------------
설명: 설문 1건의 기본 정보·공개 여부·진행 상태·응답 수 집계.

주요 컬럼:
  id              uuid PK
  slug            text UNIQUE — URL 경로 (/survey/{slug})
  title           text — 제목
  summary         text — 요약
  period_label    text — 기간 표기
  response_count  int — 누적 제출 수 (앱에서 갱신)
  target_count    int — 목표 응답 수
  status          text — '예정' | '진행중' | '종료'
  listed_public   boolean — 공개 목록 노출 여부
  response_script text — 직원용 전화 조사·응답 가이드 (20260407200000)
  created_at, updated_at

RLS: anon/authenticated — listed_public=true 이고 status='진행중' 인 행만 SELECT

--------------------------------------------------------------------------------
2.2 profiles — 사용자 프로필(역할)
--------------------------------------------------------------------------------
설명: Supabase Auth 사용자(auth.users)와 1:1. 직원·관리자·게스트 역할.

주요 컬럼:
  id          uuid PK → auth.users(id) ON DELETE CASCADE
  email       text
  role        text — super_admin | sub_admin | team_lead | employee | guest
  created_at, updated_at

RLS: authenticated — 본인 행 또는 super_admin 전체 SELECT

연관: auth.users (Supabase 기본 테이블)

--------------------------------------------------------------------------------
2.3 admin_settings — 관리자 가입키 (단일 행)
--------------------------------------------------------------------------------
설명: 직원 회원가입 시 필요한 비밀 가입키. id=1 한 행만 사용.

주요 컬럼:
  id          int PK (=1 고정)
  signup_key  text
  updated_at

RLS: 정책 없음 → anon/authenticated 직접 조회 불가. Service Role로만 접근 권장.
초기값: signup_key = 'test1234' (운영 시 반드시 변경)

--------------------------------------------------------------------------------
2.4 survey_questions — 설문 문항
--------------------------------------------------------------------------------
설명: 설문별 질문. 유형에 따라 선택지·줄 수 등 메타 사용.

주요 컬럼:
  id              uuid PK
  survey_id       uuid → surveys(id)
  order_index     int — 표시 순서
  prompt          text — 질문 문구
  question_type   text —
                    mc_single   객관식 단일
                    mc_multi    객관식 다중
                    text_single 주관식 단일
                    text_multi  주관식 다중
                    likert_7    리커트 1~7 척도 (20260407260000)
  allow_skip      boolean — 무응답 허용
  max_selections  int — mc_multi 최대 선택 개수
  text_line_count int — text_multi 답변 줄 수
  created_at

RLS: anon/authenticated — 해당 설문이 공개·진행중일 때 SELECT

--------------------------------------------------------------------------------
2.5 survey_question_options — 객관식·리커트 보기/라벨
--------------------------------------------------------------------------------
설명: 문항별 선택지. mc_single/mc_multi는 보기 문구, likert_7은 양끝 라벨(0·1번).

주요 컬럼:
  id            uuid PK
  question_id   uuid → survey_questions(id)
  order_index   int
  label         text

RLS: anon/authenticated — 공개·진행중 설문의 문항에 연결된 경우 SELECT

--------------------------------------------------------------------------------
2.6 survey_responses — 설문 제출 1건
--------------------------------------------------------------------------------
설명: 참여자가 설문을 한 번 제출할 때마다 1행.

주요 컬럼:
  id                  uuid PK
  survey_id           uuid → surveys(id)
  submitted_at        timestamptz
  respondent_user_id  uuid → auth.users(id) NULL — 비로그인 게스트는 null (20260407190000)
  respondent_kind     text — 'staff' | 'guest' (직원 vs 게스트 작업량·분석용)

RLS: INSERT/SELECT는 Service Role(서버 액션) 위주. anon 직접 INSERT 정책 없음.

--------------------------------------------------------------------------------
2.7 survey_response_answers — 문항별 답변(JSON)
--------------------------------------------------------------------------------
설명: 제출 1건당 문항별 답변. answer는 jsonb.

answer JSON 예시:
  mc_single:   { "optionId": "uuid" }
  mc_multi:    { "optionIds": ["uuid", ...] }
  text_single: { "text": "..." }
  text_multi:  { "lines": ["...", ...] }
  likert_7:    { "value": 1~7 }

주요 컬럼:
  id            uuid PK
  response_id   uuid → survey_responses(id)
  question_id   uuid → survey_questions(id)
  answer        jsonb
  UNIQUE (response_id, question_id)

RLS: Service Role 전용 쓰기·관리자 통계 조회

--------------------------------------------------------------------------------
2.8 shared_response_scripts — 공용 응답 스크립트
--------------------------------------------------------------------------------
설명: 모든 설문에서 직원이 참고할 수 있는 공통 전화 조사·메뉴얼.

주요 컬럼:
  id          uuid PK
  title       text
  body        text
  sort_order  int
  created_at, updated_at

RLS: Service Role 전용 (관리자 편집·직원 팝업은 서버에서 로드)

--------------------------------------------------------------------------------
2.9 site_settings — 홈페이지 사이트명 (단일 행)
--------------------------------------------------------------------------------
설명: 공개 사이트 왼쪽 상단 표시 이름.

주요 컬럼:
  id          int PK (=1)
  site_name   text — 예: [ OO리서치 ]
  updated_at

RLS: Service Role 전용

--------------------------------------------------------------------------------
2.10 site_nav_groups — 상단 메뉴 그룹
--------------------------------------------------------------------------------
설명: 헤더 드롭다운 1단계 (회사 소개 / 설문 조사 / 서비스).

주요 컬럼:
  key         text PK — intro | survey | service
  label       text — 표시 이름
  sort_order  int

초기 시드: intro, survey, service

RLS: Service Role 전용 (공개 홈은 서버에서 읽어 렌더)

--------------------------------------------------------------------------------
2.11 site_pages — CMS 콘텐츠 페이지
--------------------------------------------------------------------------------
설명: /p/{slug} 로 보이는 관리자 편집 페이지 본문.

주요 컬럼:
  id          uuid PK
  slug        text UNIQUE — 소문자·숫자·하이픈
  title       text
  body        text — HTML/마크다운 등 (앱에서 처리)
  updated_at

RLS: Service Role 전용

--------------------------------------------------------------------------------
2.12 site_nav_items — 메뉴 하위 항목
--------------------------------------------------------------------------------
설명: 각 nav_group 아래 드롭다운 링크. page_id로 CMS 페이지 연결 가능.

주요 컬럼:
  id          uuid PK
  group_key   text → site_nav_groups(key)
  label       text
  href        text — 내부 경로 또는 URL
  sort_order  int
  page_id     uuid → site_pages(id) NULL
  created_at, updated_at

RLS: Service Role 전용

--------------------------------------------------------------------------------
2.13 site_banners — 홈 배너
--------------------------------------------------------------------------------
설명: 홈 상단 띠 배너(top) 또는 팝업(popup). 이미지·PDF URL.

주요 컬럼:
  id            uuid PK
  title         text — 관리용·접근성 (상단 배너는 화면에 미표시 가능)
  media_type    text — image | pdf
  file_url      text — 공개 URL
  link_url      text — 클릭 시 이동 (선택)
  is_active     boolean
  sort_order    int
  storage_path  text — Storage 객체 경로
  placement     text — popup | top (20260407250000)
  created_at, updated_at

RLS: Service Role 전용

--------------------------------------------------------------------------------
3.1 버킷: site-page-assets
--------------------------------------------------------------------------------
마이그레이션: 20260407230000_site_page_assets_storage.sql

설명:
  - CMS 페이지 본문·배너 업로드 파일 저장
  - public 버킷, 최대 10MB
  - 허용 MIME: image/jpeg, png, gif, webp, application/pdf

객체 경로 예:
  - pages/...           페이지 본문 에셋
  - banners/popup/...   팝업 배너
  - banners/top/...     상단 배너

정책: storage.objects — bucket_id='site-page-assets' 공개 SELECT

※ storage.buckets, storage.objects 는 Supabase 내장 스키마입니다.

      admin_settings, shared_response_scripts, site_* 테이블

    - 업로드: Service Role
